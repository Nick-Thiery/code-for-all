So far you've built projects with Lovable and Claude Code. This module is about where that code goes next: GitHub to keep it, and Vercel to turn it into a live website.

GitHub is your project's online home. A GitHub account is free. You'll sign in to it in a session, in [lesson 5](/module-6/get-your-code-into-github).

## Store, share, collaborate

1. **Store.** Keep all your project files and their history in one location. This place is called the repository.
2. **Share.** Easily make your work accessible. You can make it public so that anyone can see, use, and learn from what you have done.
3. **Collaborate.** Work with your friends or co-workers without overwriting each other's <Term def="all the code in a project.">codebase</Term>.

<KeyTerm term="Repository">
The one location where all your project files and their history are kept. On GitHub, it's your project's online home. People call it a **repo** for short.
</KeyTerm>

A project's history means every version of every file, not only the latest one.

### An everyday comparison

Think of the save points in a video game. Each time you reach one, the game keeps a copy of where you are. If something goes wrong later, you can go back to an earlier save.

A repo keeps save points for your project. Each one has a short note saying what changed, like "Added a contact page". You can look back at any of them, and nothing you saved is lost when you make a new one.

### A worked example

Say your project is a website about your football team.

1. **Monday:** you add a fixtures page and save it to your repo with the note "Added fixtures page".
2. **Tuesday:** you change the colours, and now the menu has disappeared.
3. **Wednesday:** you open your repo's history on GitHub. Monday's version is still there, so you can see exactly what the menu looked like before Tuesday's change, and put it back.

That's **store**. If a friend helps with the site, you both send your work to the same repo, and GitHub keeps track of who changed what. That's **collaborate**.

## How it works

Your computer and GitHub each keep a copy of your project.

Git is the tool that keeps track of the versions. GitHub is the website that stores them online.

- **Git** runs on your computer. It saves the snapshots of your project. Claude Code uses it for you when you ask it to save or send your work.
- **GitHub** is a website. It keeps a copy of your repo online, so it's safe if your laptop breaks, and so other people can work on it too.

You don't need to learn Git's commands. In this course, Claude Code or Lovable runs them for you. You do need to know the words for what they do, which is the next lesson.

## Public or private?

When you make a repo, you choose who can see it ([About repositories](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories)):

- **Public:** anyone on the internet can see it, and everything you've ever saved to it.
- **Private:** only you, and people you invite, can see it.

In this course, make your own repos **Private**. You'll still be able to put your website live with Vercel. Public repos are for code you're happy for the whole world to read, like the open source projects in this module's Challenge.
