You've pasted the handoff prompt, and Claude Code has fetched your design. Once it starts, it works on its own ([lesson 3](/module-5/what-claude-code-actually-does)). But it won't start by itself.

<HandsOn />

## After the handoff

This part needs access; see [how hands-on access works](/access).

1. **It waits for you.** It won't build on its own: you type an instruction first.
2. **Tell it to build.** Example prompt:

   ```prompt title="Tell it to build"
   Reconstruct this design into a working website. Split it into index.html, styles.css and script.js, and make sure it actually runs.
   ```

3. **Watch it work.** Hit a usage limit? Leave it open and wait for the reset time: it carries on by itself.
4. **Make it actually work.**

   ```prompt title="Make it actually work"
   Make the sign-up form really save what people type.
   ```

Don't skip step 4. A sign-up form can look finished and still do nothing with what people type.

Here's each step in detail.

## Step 1: it waits for you

After you paste the handoff prompt, Claude Code fetches your design and then waits for your next instruction. If you see it has already started building, let it finish and go to step 3.

## Step 2: tell it to build

1. Click in Claude Code's message box.
2. Copy the "Tell it to build" prompt above and paste it in. Or use this longer one, which asks Claude Code to keep your design exactly as it is. It's only an example:

   ```prompt title="Example: build it, and keep the design"
   Build this design as a working website using plain HTML, CSS and JavaScript, split into index.html, styles.css and script.js. Keep the colours, fonts, spacing and words exactly as in the design. Then tell me how to open it in my browser, and list anything that differs from the design.
   ```

3. Press Enter.

## Step 3: watch it work

Claude Code now works on its own. You should see it read your design, then make the files one at a time.

<Figure src="/lessons/module-5/claude-code-created-three-files.png" alt="A Claude Code window with the prompt 'Reconstruct this design into a working website. Split it into separate files and make it run.', then three ticks: Created index.html, Created styles.css and Created script.js, and an empty box reading 'Type / for commands'." width={1044} height={867} caption="Claude Code creating index.html, styles.css and script.js. The prompt in this picture is shorter than the example prompt above." />

- **If it asks permission** to make a file or run a command, read what it wants to do. If it's working in your website folder, allow it. ([Choose a permission mode](https://code.claude.com/docs/en/permission-modes))
- **If it stops at a usage limit**, leave Claude Code open and wait for the time in the message. It carries on by itself after the reset. If it doesn't, type `continue` then. Never run `/usage-credits`: it buys extra usage. ([Wait for a usage limit to reset](https://code.claude.com/docs/en/interactive-mode#wait-for-a-usage-limit-to-reset))
- **When it's finished**, it stops and the message box is empty again.

**Check it worked.** Open your website folder. You should see `index.html`, `styles.css` and `script.js` in it. There may be other files too, like the design files from the handoff.

### Open your site in your browser

There are three ways. Start with the first.

1. **Open the file.** In your website folder, double-click `index.html`. Or drag it into a Chrome window, or in Chrome press Ctrl+O (Cmd+O on a Mac) and choose it. ([MDN: How do you set up a local testing server?](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Tools_and_setup/set_up_a_local_testing_server))

   You should now see your website. The address bar starts with `file://`. That means the browser is reading the file straight from your computer.

2. **In the Claude Code desktop app:** click `index.html` where it appears in the chat. It opens in the app's **Browser** pane, next to the chat. You can also ask Claude to preview the site there. ([Claude Code desktop: preview your app](https://code.claude.com/docs/en/desktop#preview-your-app))

3. **With a local server.** Some sites don't work from `file://`. If your page is blank and the Console (lesson 5) says "Cross-origin request blocked", you need a <Term def="a small program on your own computer that serves your website, so you can open it at an address like localhost:8000.">local server</Term>. Open a terminal in your website folder and run:

   <CommandBlock>{"python3 -m http.server"}</CommandBlock>

   Then open `http://localhost:8000` in Chrome. This needs Python on your computer. If the command isn't found, ask Claude Code to start a local server for you instead.

### Compare it with your design

Put your design and your site side by side. Do the colours, words and spacing match? If something's different, tell Claude Code. Anthropic's own advice is to ask Claude to compare the result with the original, list the differences and fix them. ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)) For example:

```prompt title="Example: match the design"
Compare the website you built with my design. List everything that's different, then fix it so it matches.
```

After each fix, reload the page in your browser to see the change: Ctrl+R (Cmd+R on a Mac).

## Step 4: make it actually work

1. Paste the "Make it actually work" prompt above into Claude Code and press Enter.
2. Wait for it to finish, then reload your site.
3. **Check it worked.** Fill in the form with a made-up name, like "Test Person", and click the button. Something should happen: a thank-you message, or the form clearing. To see where it went, ask:

   ```prompt title="Example: where did it go?"
   Where does my sign-up form save what people type? Explain it simply, and tell me how I can check it worked.
   ```

### Where do the sign-ups go?

Your site is just files, with nothing running on a server to collect sign-ups. So Claude Code will probably use <Term def="a small store inside a web browser where a website can keep a little information on that device.">localStorage</Term>. ([MDN: localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage))

That means:

- What someone types stays in **their own browser**, on their own device.
- **You, the owner, never see the sign-ups.** Nothing is sent to you.

That's fine for practice. A real sign-up list needs a place online to keep everyone's details, which you'll meet in [Module 8](/module-8/what-your-site-cant-do).

Names and email addresses are personal information. Test your form with made-up details, never real people's. Don't ask real people to sign up until you know where their details go and who can see them.
