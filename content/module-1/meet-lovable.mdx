Lovable is a <Term>vibe coding</Term> tool. You describe what you want, and it builds it: the pages, the code and the layout. You'll use it for the rest of this module and in Module 2.

Lovable runs in your browser. There's nothing to install, and you don't pay for it: access comes through your Code for All session.

These steps come from Lovable's official guide, [Getting started](https://docs.lovable.dev/introduction/getting-started). Lovable changes often, so a button might look a little different from what's described here. If it does, look for one that does the same job.

## Open Lovable and experiment

This part needs access; see [how hands-on access works](/access).

<Callout kind="tryit">
Open Lovable and try any one-line idea. Type what you want to build in a single sentence and see what it makes.
</Callout>

Need an idea? These are only examples. Pick one or make up your own:

- "A website for a made-up bakery that sells cupcakes."
- "A page that shows a random fun fact when you press a button."
- "A homework planner with a list for each day of the week."

It doesn't have to be good. This is about seeing what Lovable does with a short <Term>prompt</Term>. In [lesson 4](/module-1/the-art-of-prompting) you'll see why a longer one works better.

Here's how, step by step.

1. Open [Lovable](https://lovable.dev) and log in with the access your Code for All session gives you.

   You should now see the dashboard. In the middle is a big box for your prompt. It says "Ask Lovable to create…".

   <Screenshot caption="The Lovable dashboard: the prompt box in the middle, with the mode picker beside the send button.">Lovable's dashboard with an empty prompt box and the mode picker set to Build, from a neutral account with no names or avatars</Screenshot>

2. Check the mode. Beside the send button is the <Term def="the menu by Lovable's prompt box that picks Build, Chat or Plan. Build is the one that makes things.">mode picker</Term>. Make sure it says **Build**.

   If it says **Chat** or **Plan**, click it and choose **Build**. Chat only talks about your idea, and Plan writes a plan first. Neither builds a website straight away. Lovable remembers the last mode you picked in that browser, so check it each time. ([Lovable's guide to the dashboard](https://docs.lovable.dev/introduction/dashboard-overview))

3. Type your one-line idea into the box.

4. Click the send button.

5. Pick a look. For a first prompt, Lovable usually shows **three design directions** side by side, or asks you a few questions about fonts, colours and layout. Click the one you like best, then click **Submit**.

   Want to tweak a direction first? Type in its **Describe changes** box. Picking a look doesn't cost anything extra. If your prompt already describes the look, Lovable may skip this step and start building. ([Lovable's guide to design directions](https://docs.lovable.dev/features/design-guidance))

6. Wait while it builds. The first version takes a few minutes, and you can watch it take shape.

   If Lovable stops to ask you a question, pick an answer or skip it.

7. **Check it worked.** You should now see the editor: a chat on the left and your new website on the right. If you see a website, you've built your first project.

## Find your way around

The editor has two halves.

- **The chat (left).** This is where you talk to Lovable. To ask for a change, type in the box at the bottom and press Enter. Ask for one change at a time. You can type while Lovable is still working; it reads your message when it gets to a stopping point. ([Lovable's guide to the chat](https://docs.lovable.dev/features/projects/chat))
- **The <Term def="the live version of your website in Lovable's editor. It changes as Lovable builds.">preview</Term> (right).** This is your website, working. Click around it like a visitor would.

Above the preview is a device switch. Use it to see your site in **Desktop view**, **Tablet view** or **Mobile view**. Always check Mobile view: lots of people will open your site on a phone. ([Lovable's guide to the preview](https://docs.lovable.dev/features/projects/preview))

At the bottom centre of the preview is the **preview toolbar**. It lets you point at the part you want to change instead of describing where it is. ([Lovable's guide to the preview toolbar](https://docs.lovable.dev/features/preview-toolbar))

- **Select elements**: click a part of the page, then type the change you want in the chat.
- **Edit text inline**: click some words on the page and type new ones. A limited number of these are free each day.
- **Draw annotation**: sketch on the page, then describe the change.
- **Add a comment**: pin a note on the page for later. This is free.

Older videos call this "Visual edits". The preview toolbar replaced it. If you can't see the toolbar, look above the preview, near **Share** and **Publish**, for the icon that turns it on.

### The three modes

The mode picker sits beside the chat box too. ([Build mode](https://docs.lovable.dev/features/agent-mode), [Chat mode](https://docs.lovable.dev/features/chat-mode))

- **Build** makes changes to your site. This is the one you'll use most. (Older videos call it Agent mode.)
- **Chat** talks about your site but never changes it. Use it to ask questions, like "Why does the menu look squashed on a phone?" When a change is needed, it offers a **Start building** card.
- **Plan** writes a plan for you to approve before anything is built.

## Try the editor

This part needs access; see [how hands-on access works](/access).

1. Click **Mobile view** above the preview.

   You should now see your site squeezed to the width of a phone. Does everything still fit?

2. Click **Desktop view** to go back.
3. In the chat box, ask for one small change. For example:

   ```prompt title="Example: one small change"
   Make the main heading bigger.
   ```

   Make sure the mode says **Build**, then press Enter. You should see the heading change in the preview.

4. Now undo it. Under Lovable's latest reply in the chat, click **Undo latest edit**.
5. **Check it worked.** The heading in the preview should be back to how it was before.

## Undo a change

There's no save button. Lovable saves every change as a new version, so you can always go back. ([Lovable's guide to version history](https://docs.lovable.dev/features/projects/history))

- **Undo the last change:** click **Undo latest edit** under Lovable's latest reply. It happens straight away, with no "Are you sure?".
- **Go back further:** under an earlier reply, click **Revert to this version**, then confirm.
- **Look before you go back:** click **History** next to the project name. Click a version to look at it. Click **Back to latest** to return, or **Revert** to restore that version.

Going back doesn't give back the credits the change used.

## Credits: how much you can build

Every change you ask for in Build mode uses <Term def="Lovable's allowance for building. Each change you ask for uses some.">credits</Term>. On Lovable's Free plan you get 5 credits a day, up to 30 a month. They don't roll over: credits you don't use are gone the next day. New credits arrive at midnight UTC, which is 8am Singapore time. ([Lovable's guide to credits](https://docs.lovable.dev/introduction/credits-and-usage))

Big changes cost more than small ones. Lovable's own examples:

- Making a button grey: about half a credit.
- Removing the footer: just under 1 credit.
- Building a landing page with images: about 2 credits.

These are only examples, and real costs vary. To see what a change cost, open the **More options** menu on Lovable's reply and look for **Credits used**.

Some things don't use credits: picking a design direction, adding a comment, and a limited number of inline text edits each day. Plan mode costs 1 credit per message.

If you run out, Lovable stops building until your credits come back. Anything you've already made is safe. Your Code for All access may come with a different allowance from the Free plan, but the idea is the same: plan your change before you send it.

## Find your project again

Lovable keeps all your projects. To open one again: ([Lovable's guide to the dashboard](https://docs.lovable.dev/introduction/dashboard-overview))

1. Go to the dashboard at [lovable.dev](https://lovable.dev). Inside a project, the menu icon at the top left opens the same sidebar.
2. In the sidebar, click **Recents** for what you opened last, or **Projects** for everything.
3. Can't see it? Press Ctrl+K (Cmd+K on a Mac) and search for its name.
