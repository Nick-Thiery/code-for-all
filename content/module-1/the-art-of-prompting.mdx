Lovable builds what you ask for. Whatever you leave out, it guesses. So the way you ask decides what you get.

Here's the same request three times: bad, better and strong.

<PromptLadder>

<LadderPrompt level="Bad" prompt="Create a website for my course" leavesOut={["Role", "Target audience", "Core pages", "Design style", "Output required", "Key features"]}>

It doesn't say what the course is, who it's for, which pages it needs or how it should look. Lovable has to guess all of it.

</LadderPrompt>

<LadderPrompt level="Better" prompt="Create a modern website for my coding course with a homepage and lessons." leavesOutLabel="Still missing" leavesOut={["Role", "Target audience", 'Design style ("modern" is vague)', "Output required", "Key features"]}>

Better: it says what kind of course it is and names two pages. But "modern" could mean almost anything, and there's still no audience.

</LadderPrompt>

</PromptLadder>

The strong prompt has seven parts, each with one job.

<StrongPrompt parts={[
  {
    name: "Role",
    text: "Role: You are an expert educational web designer and full-stack developer.",
    does: "tells the AI what kind of expert to be, so it makes the choices that expert would make.",
  },
  {
    name: "Goal",
    text: "Goal: Create a responsive website for a 15-lesson course called “Vibe Coding: Build Apps with Lovable & GitHub.”",
    does: "says exactly what to build, including its name and size.",
  },
  {
    name: "Target audience",
    text: "Target audience: High-school and early-college students with little to no coding experience.",
    does: "says who it's for, so the words, layout and difficulty suit them.",
  },
  {
    name: "Core pages",
    text: "Core pages required:\n1. Landing page (course overview + value proposition)\n2. Curriculum page (15 lessons with goals and agendas)\n3. Lesson page template (objectives, agenda, exercises)\n4. About page (instructor + course philosophy)\n5. Resources page (GitHub links, tools, templates)",
    does: "lists every page, so nothing gets left out and nothing gets made up.",
  },
  {
    name: "Design style",
    text: "Design style:\n1. Modern, playful, and approachable\n2. Light background, bold headings\n3. Friendly typography (not corporate)",
    does: 'describes the look in real words, not just "modern" or "nice".',
  },
  {
    name: "Output required",
    text: "Output required:\n1. Folder structure\n2. Core page code\n3. Reusable lesson template\n4. Brief explanation of design decisions\n5. Build the site so it can be easily expanded with more lessons later.",
    does: "says what you want back: code you can use, organised the way you need it.",
  },
  {
    name: "Key features",
    text: "Key features:\n1. Clean, student-friendly UI\n2. Clear call-to-action buttons (Enrol / Start Lesson)\n3. Mobile-first design\n4. Easy navigation between lessons",
    does: "lists the must-haves that make the site easy to use.",
  },
]} />

<Callout kind="tip">
The bad prompt leaves out the audience, the pages and the style. Check your own prompts for those three first.
</Callout>
