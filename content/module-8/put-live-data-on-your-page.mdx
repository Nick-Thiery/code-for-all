Time to fix the second thing your site can't do. You'll use the weather <Term>API</Term> from [lesson 2](/module-8/what-an-api-is) to put live data on your page.

The weather API is free and needs no account or key.

It's the door from lesson 2 again. This time your own page does the knocking.

## 1. Open any project

This part needs access; see [how hands-on access works](/access).

Open your [Wordle project](/module-7/recreate-wordle), or any project.

1. **Pick a project that's already live on Vercel.** That's how you'll see the change on the internet. Not connected yet? [Module 6](/module-6/connect-to-vercel) shows how.
2. **Open it in Claude Code**, the way you did in [Module 6](/module-6/get-your-code-into-github):
   - **Desktop app:** in the **Code** tab, choose **Local** and select the project's folder.
   - **Terminal:** `cd` into the project's folder, then run `claude`.
   - **Claude Code on the web:** choose the project's repository before you start.

   You should now see Claude Code ready for a message, working in your project's folder or repository. Check the name: it should be the project that's connected to Vercel. This is what "link the chat to the correct repo" means.

## 2. Paste the prompt into Claude

```prompt title="Paste this into Claude"
When my page loads, fetch this URL:

https://api.open-meteo.com/v1/forecast?latitude=1.29&longitude=103.85&current=temperature_2m

and show the current temperature in a small box at the top of the page.
```

This will update your site with the live temperature of Singapore.

1. **Paste the prompt and send it.**
2. **Approve the changes.** Claude Code shows each change before it makes it. Choose **Yes** in the terminal, or **Accept** in the desktop app.

   You should now see Claude say what it changed, usually your main page (often `index.html`), with a new box and a few lines of code that fetch the link. If it asks which page to add the box to, tell it the main one.

### Add the credit

Open-Meteo's free data comes with one rule: say where it came from. Its licence asks for a link next to the data ([Open-Meteo licence](https://open-meteo.com/en/licence)). Send this next:

```prompt title="Example: add the credit"
Under the temperature box, add a small link that says "Weather data by Open-Meteo.com" and goes to https://open-meteo.com/
```

You should now see Claude add one link under the box.

### Optional: show Singapore time

If your box shows the time as well as the temperature, it will be 8 hours behind. Open-Meteo gives times in GMT unless you ask for a time zone ([Open-Meteo docs](https://open-meteo.com/en/docs)). Adding `&timezone=Asia%2FSingapore` to the end of the link fixes it. `%2F` is how a `/` is written inside a link.

```prompt title="Example: Singapore time"
Add &timezone=Asia%2FSingapore to the end of the open-meteo URL, and show the time the temperature was updated next to it.
```

### What Claude added

Your code will look different, and that's fine. Here's an example of the kind of thing Claude writes. We wrote it from the [MDN guide to fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) and the Open-Meteo docs.

```html title="Example: index.html"
<div id="weather-box">Loading Singapore's temperature…</div>
<a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>

<script>
  async function showTemperature() {
    const url = "https://api.open-meteo.com/v1/forecast?latitude=1.29&longitude=103.85&current=temperature_2m&timezone=Asia%2FSingapore";
    const box = document.getElementById("weather-box");
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error(`Response status: ${response.status}`);
      const data = await response.json();
      const temp = data.current.temperature_2m;
      const unit = data.current_units.temperature_2m;
      box.textContent = `Singapore right now: ${temp}${unit} (updated ${data.current.time.slice(11)})`;
    } catch (error) {
      box.textContent = "Couldn't load the weather. Try again later.";
      console.error(error.message);
    }
  }
  showTemperature();
</script>
```

Read it like this:

- **`fetch(url)`** knocks on the door: it sends the request.
- **`response.ok`** checks the answer isn't an error. `fetch` only fails by itself when there's no connection at all, so the code has to check this.
- **`response.json()`** turns the answer into data the code can use.
- **`data.current.temperature_2m`** picks out the number, the same place you found it in [lesson 2](/module-8/what-an-api-is).
- **`box.textContent = …`** puts it in the box. If anything goes wrong, the box says so instead of staying blank.

### Push it

<Callout kind="tip">
Remember to link the chat to the correct repo and push the changes. Also make sure that repo is connected to Vercel so that you can see changes. [Module 6](/module-6/connect-to-vercel) shows how to connect it.
</Callout>

1. **Ask Claude Code to push:**

   ```prompt title="Example: push the change"
   Commit these changes with a clear message and push them to GitHub.
   ```

   Working on a branch, as in [Module 7](/module-7/make-your-own-branch)? Open a pull request and merge it, so the change reaches main and your live site.
2. **Wait about a minute.** Every push to GitHub makes Vercel rebuild your live site automatically.

## 3. Check it worked

Refresh the page. A real temperature, from a real weather service.

1. **Open your live link** from Vercel and refresh it.

   You should now see a small box at the top of the page with Singapore's temperature in °C, and the "Weather data by Open-Meteo.com" link under it.
2. **Compare it** with [the open-meteo link from lesson 2](https://api.open-meteo.com/v1/forecast?latitude=1.29&longitude=103.85&current=temperature_2m). The `temperature_2m` number there should match your box.
3. **Reload your page.** You'll usually see the same number. That's normal: Open-Meteo's current temperature updates every 15 minutes, not every second. Come back later and it may have changed.

If the box says it couldn't load, or stays empty, look in the Stuck box below.

**Check it worked:** your live site shows Singapore's real temperature in a small box at the top, with the Open-Meteo credit link, and the number matches the open-meteo link.
