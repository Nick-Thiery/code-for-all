You will hit one. That's normal: a merge conflict doesn't mean you broke anything.

## Why it happens

This tends to happen when two branches change the **same line**. Instead of assuming which is correct, Git stops and asks you.

## What it looks like

Say main and your branch, alex-keyboard, both changed the Wordle page title. Git shows you this:

```html
<<<<<<< HEAD
<h1>Wordle by Team 3</h1>
=======
<h1>Team 3 Wordle</h1>
>>>>>>> alex-keyboard
```

Git shows you both versions: what's on main (top) and what's on your branch (bottom).

- The top version sits between `<<<<<<< HEAD` and `=======`. That's main.
- The bottom version sits between `=======` and `>>>>>>> alex-keyboard`. That's your branch, named on the last line.

## How to fix it

1. Keep the version you want, or combine both versions of code.
2. Delete the `<<<`, `===` and `>>>` marker lines.
3. Commit again.

For example, to keep main's title, those five lines become one:

```html
<h1>Wordle by Team 3</h1>
```

## The escape hatch

Paste the entire block of code into Claude Code, then say:

```prompt title="The escape hatch"
I have a merge conflict in <name of the file>. Please help me resolve it and keep all features working.
```

Replace `<name of the file>` with the name of the file that has the conflict.
